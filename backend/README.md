# InvoiceX Backend

FastAPI implementation of `docs/FRONTEND_API_CONTRACT_DRAFT.md`.

## Run

The repository's existing `agent/` package must be present beside `backend/`.

```powershell
cd backend
Copy-Item .env.example .env
uv sync --all-groups
uv run uvicorn invoicex_backend.main:app --reload --port 8000
```

- Swagger UI: `http://localhost:8000/api/docs`
- OpenAPI JSON: `http://localhost:8000/api/docs-json`
- API base URL: `http://localhost:8000/api/v1`

## Local Privy signup

The shared InvoiceX Privy development App ID is included in both environment
examples because it is public. Each developer must receive the App Secret and
verification public key through the team's secret-sharing channel; never commit
either value or send them to the frontend.

1. Copy `backend/.env.example` to `backend/.env`.
2. Set `PRIVY_APP_SECRET` and `PRIVY_VERIFICATION_KEY` in `backend/.env`.
3. Copy `frontend/.env.example` to `frontend/.env.local`.
4. Start the backend on `http://localhost:8000` and the frontend on
   `http://localhost:5173`.
5. Open `http://localhost:5173/signup`. Do not substitute `127.0.0.1`; the
   Privy development app allows the exact `localhost:5173` origin.

Every developer gets a separate local SQLite database and can register a
separate Privy user-owned Solana wallet. Logging in with the same email against
the same Privy app reuses that user's existing Privy wallet, while InvoiceX
company/profile data remains local until a shared backend database is deployed.

Set `AGENT_MODE=real`, `VERTEX_AI_PROJECT_ID`, and `VERTEX_AI_LOCATION` to use
Gemini through Vertex AI and Application Default Credentials. Without a Vertex
AI project, document analysis returns a configuration error instead of
fabricated Demo extraction data. Use `AGENT_MODE=mock` explicitly only for
deterministic tests and demos.
For the shared Devnet flow, set `SOLANA_MODE=privy` explicitly so
the server fails during startup when Privy configuration is missing rather than
falling back to mock execution. The older `direct` adapter remains only for
isolated local tests with developer-managed keypairs.

## Real Devnet RWA demo

The Devnet demo issues one indivisible SPL token per invoice. Privy manages
three service wallets: Treasury / Agent Vault holds the investor's deposited
USDC, Issuer / Escrow mints and holds the RWA, and Sponsor pays Devnet SOL
fees. External supplier and investor wallets remain browser wallets; neither
their private keys nor Privy secrets are sent to the frontend.

`PRIVY_SPONSOR=false` is intentional for this design. It disables Privy's
separate managed gas-sponsorship product; the configured Sponsor wallet is the
actual Solana fee payer for the transaction.

For the local Devnet flow, set `PRIVY_BROADCAST_MODE=rpc`. Privy signs using
the configured service-wallet keys, then the same `SOLANA_RPC_URL` that
provided the recent blockhash broadcasts the fully signed transaction. This
does not export a wallet private key from Privy.

1. Copy `.env.example` to `backend/.env` and set the Privy App ID / Secret,
   Treasury, Issuer, and Sponsor wallet values. Keep the App Secret in Secret
   Manager for Cloud Run; do not share it through Git or the frontend.

2. Fund the Sponsor wallet with Devnet SOL and fund the investor's external
   wallet with Circle Devnet USDC using the Mint configured in `SOLANA_USDC_MINT`.
   If the Circle faucet is rate-limited, a developer can fund **up to the demo
   limit** from the existing Agent Vault using the local-only command below.
   Review the dry run first; `--execute` is required to broadcast anything.

   ```powershell
   uv run python scripts/fund_devnet_wallet.py --wallet <INVESTOR_PUBLIC_ADDRESS> --amount-usdc 1
   uv run python scripts/fund_devnet_wallet.py --wallet <INVESTOR_PUBLIC_ADDRESS> --amount-usdc 1 --execute
   ```

   The Treasury authorizes the USDC transfer and Sponsor pays the Devnet SOL
   fee. This is deliberately not exposed as an HTTP API.

3. Start the backend and frontend with `VITE_USE_MOCK_API=false`. The investor
   signs the policy and Vault deposit in their browser wallet. A qualifying RWA
   then transfers atomically: Agent Vault stablecoin to the supplier and the
   escrowed RWA to Agent Vault.

## Verify

```powershell
uv run ruff check src tests scripts
uv run pytest
uv run python scripts/stress_api.py --iterations 500 --concurrency 25
```

The stress runner uses deterministic Agent and Solana adapters, so it does not
consume Gemini quota or submit on-chain transactions.

## Pricing fixture and local demo rebuild

The canonical demo pricing fixture is generated by the backend Decimal/base-unit
calculator. Verify it has not drifted with:

```powershell
uv run python scripts/generate_demo_pricing_fixture.py --check
```

To rebuild a local SQLite demo database, pass the exact database path and the
explicit confirmation flag. The script first creates a timestamped adjacent
backup, recreates only the local schema, and never modifies existing Devnet
mints or historical chain transactions:

```powershell
uv run python scripts/rebuild_demo_data.py ./invoicex-rwa.sqlite3 --yes
```
