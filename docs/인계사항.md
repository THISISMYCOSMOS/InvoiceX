# 인계사항

## 현재 완료된 사항

- 최신 Devnet 구현을 `work` 브랜치에 병합했습니다.
- backend 19개, agent 52개, frontend 67개 테스트가 통과했습니다.
- frontend 프로덕션 빌드가 성공했습니다.
- Agent Vault, RWA 발행·에스크로, Gas Sponsor 역할의 서비스 지갑을 준비했습니다.
- 기존 Firestore `(default)` 데이터베이스는 더 이상 backend 상태 저장소로 사용하지 않습니다.

## 남은 작업

### 1. 지갑 및 테스트 토큰 준비

- 공급기업과 투자자 외부 지갑 주소를 확정하고 총 5개 역할별 주소를 공유합니다.
- 투자자 지갑에 Devnet 테스트 USDC를 지급합니다.
- Gas Sponsor 지갑에 Devnet SOL을 충전합니다.
- 실제 테스트에 사용할 USDC mint와 decimals를 하나로 확정합니다.
  - 현재 환경 설정 예시 mint: `4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU`
  - decimals: `6`

### 2. 투자자 Mandate 및 Vault 예치

- 투자자가 외부 지갑으로 Mandate에 서명합니다.
- 투자자 USDC를 Agent Vault로 실제 예치합니다.
- 투자자 지갑에 SOL이 없는 상태에서 Sponsor가 수수료를 부담하는지 확인합니다.
- 예치 트랜잭션과 Sponsor SOL 전후 잔액을 기록합니다.

### 3. RWA 실제 발행

- 구매기업 확인과 Risk Passport가 끝난 인보이스만 발행 대상으로 처리합니다.
- 인보이스마다 RWA 토큰 1개를 Solana Devnet에 발행합니다.
- 발행한 RWA를 서비스 Escrow에 보관합니다.
- RWA mint 주소와 발행 트랜잭션 Explorer 링크를 저장합니다.

### 4. Agent 자동 매수

- 자동 매수 직전에 다음 조건을 서버에서 다시 확인합니다.
  - Risk Score
  - 허용된 구매기업
  - 건별 및 총 투자 한도
  - 만기
  - Mandate 만료 여부
  - Agent Vault USDC 잔액
- 조건 통과 시 사람의 매수 버튼 없이 자동 매수를 실행합니다.
- 한 트랜잭션에서 아래 두 이동이 함께 처리되는지 확인합니다.
  1. Agent Vault USDC → 공급기업 지갑
  2. Escrow RWA → Agent Vault

### 5. 필수 검증 및 증빙

- 공급기업 지갑의 USDC 증가를 확인합니다.
- Agent Vault의 RWA 보유를 확인합니다.
- 수수료가 투자자 지갑이 아닌 Sponsor 지갑에서 차감되는지 확인합니다.
- 같은 인보이스를 여러 번 요청해도 USDC가 중복 지급되지 않는지 확인합니다.
- 조건 미충족 또는 Vault 잔액 부족 시 자동 매수가 실행되지 않는지 확인합니다.
- RWA 발행, Vault 예치, 자동 매수의 Explorer 링크와 전후 잔액을 남깁니다.

### 6. GCP backend 전환

- FastAPI backend를 Cloud Run에 배포하고 서비스 URL을 공유합니다.
- Secret Manager API를 활성화하고 Gemini, Privy, RPC 및 서비스 지갑 관련 비밀값을 저장합니다.
- Cloud SQL for PostgreSQL 인스턴스와 `invoicex` 데이터베이스를 만들고 backend 상태 저장소로 연결합니다.
- private Cloud Storage bucket을 만들고 인보이스 PDF·이미지를 저장합니다.
- Cloud Run 서비스 계정에는 Secret Accessor, Cloud SQL Client, 해당 bucket의 Storage Object User 권한만 부여합니다.
- 별도의 Cloud Logging 구성은 데모 범위에서 생략할 수 있습니다.

## 최종 공유 목록

- 사용한 지갑 공개주소 5개
- 테스트 USDC mint 주소, decimals 및 지급 방법
- RWA 발행, Vault 예치, 자동 매수 Explorer 링크
- 공급기업 USDC 증가, Vault RWA 보유, Sponsor SOL 차감 결과
- 중복 실행 및 조건 미충족 테스트 결과
- Cloud Run URL
- Cloud SQL 및 Cloud Storage 연결 여부
